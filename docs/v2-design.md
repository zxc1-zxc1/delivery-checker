# 实施交付环境巡检工具 V2 设计

## 1. 项目目标

将V1的单文件学习项目升级为结构清晰、可测试、可部署、可维护的工程化命令行工具，为软件实施和交付前检查提供可复用的巡检能力。

## 2. 使用场景

- 部署前检查服务器磁盘、端口和HTTP服务；
- 检查业务数据库能否连接并执行基础查询；
- 保存巡检历史并导出报告；
- 在自动化任务中根据退出状态码判断巡检结果；
- 根据日志和错误类型协助实施人员定位问题。

## 3. 功能范围

### 3.1 配置管理

- 使用JSON配置巡检任务；
- 校验必填字段、端口范围、URL、阈值和超时时间；
- 配置错误时给出明确提示；
- 数据库密码等敏感信息通过环境变量提供。

### 3.2 巡检能力

- 磁盘剩余空间检查；
- TCP端口连通性检查；
- HTTP响应状态检查；
- MySQL连接与SELECT 1检查；
- 支持超时、重试和错误分类；
- 支持相互独立的任务并发执行。

### 3.3 结果处理

- 统一巡检结果数据结构；
- 记录状态、详情、耗时、检查时间和重试次数；
- 保存到SQLite；
- 查询历史记录；
- 导出CSV报告；
- 统计PASS和FAIL数量。

### 3.4 日志与退出码

- 同时输出终端信息和日志文件；
- 日志不得记录数据库密码；
- 退出码0：全部通过；
- 退出码1：至少一项巡检失败；
- 退出码2：配置错误或程序运行错误。

## 4. 暂不包含

- 账号、角色和权限系统；
- 复杂Web管理平台；
- 微服务、Kubernetes和消息队列；
- 未经实际验证的企业生产级承诺。

## 5. 模块设计

| 模块 | 职责 |
|---|---|
| cli | 解析命令行参数并组织主流程 |
| config | 读取配置、校验配置、生成任务 |
| models | 定义巡检结果、状态和错误类型 |
| runner | 执行巡检、重试和并发调度 |
| checkers | 实现磁盘、TCP、HTTP和MySQL检查 |
| storage | 负责SQLite建表、写入和历史查询 |
| reporting | 生成CSV报告和结果汇总 |
| logging | 配置终端和文件日志 |

## 6. 核心结果字段

- item：巡检类型；
- target：巡检目标；
- status：PASS或FAIL；
- message：结果说明；
- error_type：错误分类；
- checked_at：检查时间；
- duration_ms：耗时；
- attempts：实际尝试次数。

## 7. 测试原则

- 核心测试不依赖百度等外部服务；
- 使用模拟对象测试socket、HTTP和MySQL异常；
- 使用临时SQLite数据库测试存储；
- 使用临时目录测试报告导出；
- 同时覆盖正常、异常和边界情况；
- 每次重构后运行全部测试。

## 8. 验收标准

- 新安装环境能够按照README完成运行；
- 所有巡检模块职责清楚，不再集中于单个main.py；
- 配置错误、网络异常和存储异常有明确处理；
- 测试无需访问真实外部网站；
- GitHub Actions能够自动运行代码检查和测试；
- 文档包含安装、配置、运行、测试和故障排查；
- 发布V2.0.0标签，并保留V1.0.0作为历史版本。
